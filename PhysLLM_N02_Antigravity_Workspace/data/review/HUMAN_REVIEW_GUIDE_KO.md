# N02 내용 검토 지침

## 검토 단위

CSV의 한 행(`text_id`)이 기본 검토 단위입니다. 네 문체가 같은 `topic_id`에 속하므로, 각 행만 따로 보지 말고 네 문체가 같은 대상·연산·난이도를 유지하는지도 함께 비교합니다.

## 행별 필수 항목

1. **주제 적합성:** 텍스트 내용이 `topic_domain`을 실제로 다루는가?
2. **연산 일치:** `operation_id`가 설명·코드가 수행하는 연산과 일치하는가?
3. **코드 정확성:** 코드는 실행 가능한가? 결과가 의도한 연산을 수행하는가?
4. **경계 조건:** 빈 입력, 결측값, 상수 배열, 짧은 배열, 동률 등 관련 경계 조건이 다뤄지는가?
5. **설명 일치:** 자연어, 주석, 해석이 실제 코드 동작을 정확하게 설명하는가?
6. **복제/템플릿:** 다른 주제와 숫자만 다른 사실상 동일 문항인가? 이런 반복이 설계상 필요한가?
7. **누출/오염:** G0 C-Set 파일럿 텍스트가 복제되거나 calibration 용도로 부적절하게 쓰이지 않았는가?

## 기록할 필드

- `review_status`: `APPROVED`, `NEEDS_REVISION`, `REJECTED` 중 하나
- `reviewer`: 검토자 식별명(실명일 필요 없음, 프로젝트 내에서 일관된 ID)
- `rationale`: 판단 근거. 단순히 “확인”이라고 쓰지 말고 문제/통과 근거를 기술
- `reviewed_at_utc`: ISO 8601 UTC 시각(예: `2026-10-11T10:15:00Z`)

`APPROVED`는 필수 항목 모두에 문제가 없을 때만 사용합니다. `NEEDS_REVISION` 또는 `REJECTED`가 한 건이라도 있으면 동결 준비 완료로 볼 수 없습니다. 자동 코드 문법 통과는 의미적 승인과 다릅니다.

## 우선 검토

1. `code_plus_natural_language` 100개 행
2. `template_repeated_3plus = true`로 플래그 된 행
3. 과거 preflight 보고서에서 도메인 맥락 부족/템플릿 반복 경고를 받은 항목(단, 해당 보고서와 현재 CSV의 출처 해시가 다를 수 있으므로 과거 경고는 보조 신호로만 사용)
4. 나머지 prose, dialogue, academic 행

모든 400개 행에 검토 판단이 있어야 하지만, 먼저 고위험 코드 행을 검토해 주요 결함을 드러내고, 수정된 후보는 새 버전으로 만든 뒤 전체 감사를 다시 실행합니다.
